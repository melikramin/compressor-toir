# Установка compressor-toir у клиента

Служба разворачивает у вас локальную базу с данными компрессоров и наполняет её
из облака. **Наружу не открывается ни один порт** — служба сама раз в 5 минут
подключается к `com.geotek.app` по HTTPS и забирает данные. Из интернета к
вашему серверу никто не обращается.

## Требования

- Linux-сервер (Ubuntu 22.04+ / Debian 12+ или аналог), 2 ГБ RAM, 10 ГБ диска.
- Docker и Docker Compose — поставит сам установочный скрипт, если их нет.
- Исходящий доступ к `https://com.geotek.app` (порт 443). Больше ничего.
- API-ключ — выдаём мы.

## Установка

На чистом сервере всё делается одной командой — от имени root:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/melikramin/compressor-toir/main/install.sh)"
```

Она поставит Docker, если его нет, скачает проект в `/opt/compressor-toir` и
запустит установку. Каталог создавать заранее не нужно.

Если проект уже скачан:

```bash
cd /opt/compressor-toir
./setup.sh
```

Скрипт спросит четыре вещи и всё остальное сделает сам:

| Вопрос | Что отвечать |
|---|---|
| Адрес платформы | оставить как есть — `https://com.geotek.app/api` |
| API-ключ | ключ, который выдали мы (скрипт сразу проверит его на платформе) |
| Откуда подключается 1С:ТОиР | `1` — с других машин, из сети или через интернет; `2` — только с этого же сервера |
| Порт Postgres | `5432`, если свободен |

Пароли он придумает сам, поднимет контейнеры, дождётся первой синхронизации и
покажет готовые реквизиты для интегратора — **пароль показывается только там**,
запишите его сразу.

Второй запуск `./setup.sh` открывает меню обслуживания: состояние службы,
реквизиты подключения, смена API-ключа и адреса платформы, перезапуск, журнал.
Ключ и адрес проверяются на платформе до записи, поэтому опечатка не сломает
работающую службу.

### Вручную, если скрипт не подходит

```bash
cp .env.example .env
```

Заполнить в `.env`:

| Переменная | Что вписать |
|---|---|
| `API_KEY` | ключ, который выдали мы |
| `POSTGRES_PASSWORD` | придумать пароль владельца базы |
| `TOIR_1C_PASSWORD` | придумать пароль для учётки, под которой ходит 1С |
| `PG_BIND` | `0.0.0.0`, если 1С подключается с других машин; `127.0.0.1`, если 1С на этом же сервере |
| `PG_PORT` | `5432`, если порт свободен |

Запуск:

```bash
docker compose up -d --build
docker compose logs -f sync
```

Пароль для интегратора — значение `TOIR_1C_PASSWORD` из `.env`.

В логе должно появиться `такт ок: N тегов`. Служба стартует сама после
перезагрузки сервера (`restart: unless-stopped`).

## Проверка состояния

В любой момент, из каталога `/opt/compressor-toir`:

```bash
./status.sh
```

```
compressor-toir

  РАБОТАЕТ

  Последняя синхронизация  только что  (12.08.2026 14:21:02 UTC)
  Строк в таблице          10
  Данные приборов          2 мин назад
  Опрос платформы          раз в 5 мин

  Компрессоры:
    111111      3 парам.  4 мин назад
    50317504    7 парам.  2 мин назад
```

Что означает первая строка:

- **РАБОТАЕТ** — синхронизация проходит, 1С получает свежие данные;
- **СБОЙ ПОСЛЕДНЕГО ТАКТА** — один заход не удался, данные ещё свежие, обычно
  проходит само к следующему такту. Причина написана строкой ниже;
- **ДАННЫЕ УСТАРЕЛИ** — связи с платформой нет больше 15 минут, 1С читает
  старые значения;
- **НЕТ СВЯЗИ С ЛОКАЛЬНОЙ БАЗОЙ** — не поднялся контейнер `postgres`.

Команда возвращает код `0`, `1` и `2` соответственно — если нужно завести
проверку в свою систему мониторинга, ориентируйтесь на него.

### Доступ к порту

При `PG_BIND=0.0.0.0` порт Postgres открыт для всех адресов, и единственная
защита — пароль учётной записи `toir_1c`. Трафик до 1С не шифруется.

Если у машины с 1С постоянный IP, сузьте доступ до него:

```bash
ufw allow OpenSSH
ufw allow from IP_МАШИНЫ_С_1С to any port 5432 proto tcp
ufw enable
```

Строку с `OpenSSH` не пропускайте — иначе потеряете доступ к серверу по SSH.

## Данные для интегратора 1С

В справочнике «Подключения к базе данных»:

| Поле | Значение |
|---|---|
| СУБД | PostgreSQL |
| Сервер | IP сервера (или `127.0.0.1`, если 1С на этом же сервере) |
| Порт | значение `PG_PORT` из `.env` (по умолчанию `5432`) |
| База | `toir` |
| Пользователь | `toir_1c` |
| Пароль | значение `TOIR_1C_PASSWORD` из `.env` |
| Период получения данных | 5 минут |

Текст запроса чтения:

```sql
SELECT tag, value, value_text, ts FROM v_toir_1c;
```

Полный набор колонок, если нужен: `tag`, `object_id`, `serial`, `param_code`,
`param_name`, `signal_type`, `value`, `value_text`, `unit`, `ts`, `updated_at`.

- `tag` — `{серийный номер}_{КОД_ПАРАМЕТРА}`, уникален.
- `value` — число, `value_text` — то же значение для человека («Авто нагрузка»,
  «0.73 MPa»). Для кодов состояния и аварий смотреть `value_text`.
- `ts` — время данных прибора, `updated_at` — когда строку обновила платформа.
  Если оба перестали расти, данные устарели.
- Давление в МПа, наработка в часах.

Учётная запись `toir_1c` может только читать `v_toir_1c` и `v_sync_state`.
Писать или смотреть что-то ещё она не может.

## Если данные не обновляются

```bash
docker compose ps                                   # оба контейнера up
docker compose logs --tail=50 sync                  # причина в последней строке
docker compose exec postgres psql -U toir -d toir -c "SELECT * FROM sync_state;"
```

`sync_state.last_error` показывает, что именно не получилось, `last_success_at` —
когда данные обновлялись в последний раз. Служба **никогда не стирает таблицу**
при сбое: 1С продолжит читать последние удачно полученные значения.

Частые причины: нет исходящего доступа к `com.geotek.app:443`; ключ отключён на
нашей стороне (в логе `ключ отвергнут (HTTP 401)`).

Перезапуск: `docker compose restart sync`.
